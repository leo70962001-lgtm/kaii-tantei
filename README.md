# 怪異探偵部 PART BREAK

東京鬼高校・怪異探偵部の三人——改造人間のJK、吸血鬼のニート、狼人のメイド——的手繪點陣格鬥遊戲，
主打「部位破壞」：每個角色有四個可破壞的部位，打壞了外觀會變、招式與能力也會變。

- **改造人間（JK）170cm** — 義手・義足・刀・制服。義手壞了重拳變肩撞；義足壞了變慢；刀會被打飛（旋轉飛出、插在地上），走到旁邊按 ↓ 撿回來（耐久回一半）。
- **吸血鬼（ニート）152cm** — 眼鏡・筆電・拖鞋・呆毛。筆電碎了就改用牙齒和爪子，速度變快。必殺技把使い魔（蝙蝠貓）射出去。
- **狼人（メイド）165cm** — 頭飾・圍裙・封印・皮鞋。封印緞帶被打斷就會狼化：體型變大、攻擊變重、回一點血。

## 玩

直接開 `index.html`（或 `dist/index.html` 單檔版）就能玩；本機預覽：

```bash
node server.js 5200
```

| 1P | 2P | 說明 |
| --- | --- | --- |
| ← → | A D | 移動；按住後退＝防禦；連按兩下前＝衝刺、後＝後跳 |

| ↓ | S | 蹲下；蹲下攻擊＝下段（要蹲防） |

| 空中 Z / ↓Z / X | 空中 J / ↓J / K | 空中義手／空中義足（急降下蹴り，上段）／空中斬 |

| C / ↓C | L / ↓L | 影分身・居合／電磁衝撃破（光彈），連段中可取消 |

被打中的部位（頭／身／腳）決定哪個零件受損；武器（刀、筆電）只在持有者攻擊時被打才會受損。
每破壞一個部位額外扣 4 點 HP。兩勝制、每回合 60 秒。

### 管線
- `ref/cells.py` — 三張表 → `src/sprites-jk.js`：4px 格取樣、去掉標題色帶與（C 的）方框（只沿黑色像素從色帶走進去，不會吃掉人物輪廓）、以「有高瘦主體的欄」切開被刀身／殘影連在一起的相鄰格（細欄歸右側主體：表上刀與殘影都畫在人物前方）、能量／火焰效果依顏色分層（青／青綠／洋紅／橘黃種子＋擴張，人物內的小塊留給人物）、腳底錨點＝下 30%、中央 70% 寬的腿部中心、每張表以多數決判定朝向（三張都朝右，不鏡射）、被一起切到的第二個人物另立一格。`ref/cellstrips.py` 產生逐列放大檢視圖。
- `src/sprite.js` — 執行層：解碼、Scale3x／Scale2x、同一張畫被切開的格子可用表上座標復原（comp）、格內裁切（crop）、每格快取正反向畫布：人物、效果（bloom 來源）、影子剪影、殘影染色、命中白閃；`SPR.sword()` 從長刺突格取出刀身當作被打飛的刀道具。
- `src/jk-moves.js` — 招式表：每個狀態 = 格序列＋時長＋前進量＋判定框（以格 px 相對腳底錨點手寫，依表的倍率換算成世界 px）＋連段／取消／無敵／空中標籤／投擲欄位；受擊框由該格人物範圍切成頭 26%／身／腿 34%；部位破壞的錨點為固定偏移。
- `src/game.js` — 引擎不變（60Hz 模擬、判定、部位破壞、投技、投射物、氣槽與超必殺、AI、模式、HUD、three.js 畫面層），只把「畫哪個姿勢」換成「畫哪個格」：`frameImg` 直接取格畫布（各格自帶錨點）、受擊框／錨點改由格子提供、光彈用 A 表的光彈格、刀道具用 `SPR.sword()`。
- **點圖精緻化的方式（依使用者指示：整體縮小、不是貼圖、依基本特徵慢慢點細、以動作表為方向、參考網站上的點陣動作教學）**
  - **尺寸**：角色回到動作表的原生像素——站高 41px，遊戲內整數 ×2（82px），最近鄰放大、不做平滑，舞台也改成同樣的 2px 像素密度（`chunky()`：全尺寸繪製→取半→放大 ×2），整個畫面像素大小一致。判定框以格 px 手寫，×2 換算。
  - **參考**：Slynyrd「17 – Sword Attack」教學（stance → anticipation 0.1s → smear 0.05 → hit 0.1（hold）→ follow through 0.05 → recover 0.05 → overshoot 0.05，殘影用實心淡色扇形，「add creative hit effects」）、Boyle David 的八種刀連段（每招 3～4 格＋弧形殘影）、Jesse Munguia 的骷髏兵動作表（48px：idle 4 / walk 6 / attack 4–5 / death 4，平塗 4 色＋深色輪廓）。存於 ref/（不入庫）。
  - **目前遊戲用的版本（使用者選定「回到這一個版本」）**：招式表 `src/jk-moves.js` 全部使用動作表格子（A／B／C 表，站高 41px ×2），構え＝B0 兩格呼吸、袈裟斬＝A30→A31→A29→A0→B1、光彈＝A36；下面的手繪格 H0–H83 仍留在 `ref/hand.py` 與 `sprites-jk.js` 的 H 表裡，隨時可以再指回去。
  - **`ref/refine2.py` — 更精準的分析 ＋ 16-bit 風格精緻化**（依使用者給的 OMAR. 制服少女點圖、「How to draw a 16-bit RPG sprite」圖解、Pinterest 點圖教學板：線條 Original→Softer→Cleaner、2D game art 101 的一致光源／一致陰影、Slynyrd）。分析：`grid_analysis.py` 的梯度自相關顯示三張 Gemini 動作表**沒有真正的像素格**（週期峰值在 1px，是「像素風」的畫），OMAR. 參考圖則是乾淨的 3px 格（人物 157px 高）；所以舊的 4px 區塊平均會把相鄰偽像素混在一起、留下 JPEG 泥。精緻化：每個精靈像素回到原圖的 4×4（C 表 2.9×2.9）來源像素，先剔除背景色，逐像素依顏色＋在人物上的高度分類成材質（髮、膚、白上衣、藏青領、紅領巾、裙、鉻義足、絲襪、靴、刀身、刀柄、鍔、義肢虹彩、線），區塊取多數材質（臉、領巾、鍔等小特徵佔 1/4 就優先），色調＝該材質在區塊內的中位亮度對到固定 3 階色階（陰／底／亮，取自站姿圖），兩腿依「逐欄平均亮度」分成暗（絲襪）與亮（鉻）；再依圖解：剪影優先（沿用切格遮罩）、鎖定 1px 深色外框、每區 3 階色、群聚式陰影（材質內 3×3 多數決，不抖色）、簡單的臉（黑睫毛下 1px 紅眼＋白挑染）、不留半透明像素；特效層另外壓成青／洋紅／火／白各 3 階。輸出回寫 `src/sprites-jk.js`（`refined: 2`，H 表不動）、`ref/art/cells/`、`ref/art/refine2_review.png`（上＝之前、下＝之後）。
  - **`refine2.py x2` — 以 B 表為基準的「更精準更精細」版（目前遊戲用的）**：每個精靈像素只取原圖 2×2 的來源視窗，格子變成 **82px**（原圖的一半大小，是這些畫能給的極限精細度），在 480×270 世界裡 **1:1 繪製**（`src/sprite.js` SCALE A／B／C＝1、`RES`＝2 供刀道具的 41 制偏移換算；`jk-moves.js` K＝1、39 個判定框數值 ×2，世界座標的攻擊距離不變）。剪影也從原圖重取（在切格遮罩膨脹一圈的範圍內，視窗過半非背景才算人物；特效筆觸另從特效遮罩重切成青／洋紅／火／白三階）；臉在 82px 下是 2px 睫毛＋紅虹膜＋深色瞳孔＋兩三像素的白挑染。每格保留 `g41`（切格時的 41px 幾何與遮罩，打包成位元）所以可隨時回到 `python refine2.py`（41px）重跑。`src/sprites-jk.js` 因此約 4MB。
  - **`ref/analyze_b.py` — 更精細的分析（以 B 表為基準，「把圖給學進去」）**：在原圖解析度量每一格：人物框、高度、腳底線、相對於待機格的比例、眼睛位置（膚色框上半的深色團）、每種材質的實測顏色（亮度百分位＋中位彩度→三階）、輪廓顏色 (20,23,42) 與粗細（深色橫向連續長度多為 1～2 原圖 px）。結果寫到 `ref/art/analysis_b.json`，`refine2.py` 讀進去用：**尺寸漂移校正**——待機格 164 原圖 px 高但步行格只有 149～152（小 8%）、A 表拳擊格 154～155，所以直立格（寬高比 < 0.62、高度 ≥ 80%）各自縮放到待機高度，其他格取同列直立格的中位倍率（`noscale` 關閉）；**眼睛**照實測位置點（睫毛 2px、紅虹膜、瞳孔）；輪廓色改用表上實測的深藍 (20,23,42)；表上實測的調色盤（較灰、較暗）也留著（`sheetpal`），預設仍用站姿圖的乾淨色。
  - **「用這圖來做判斷」→ B 表的向量重繪版 `ref/jk_actions3v.jpg`**（VECTOR GRAPHICS CHARACTER ACTION ASSET SHEET，格子有編號、線條乾淨）：與 B 表同尺寸同版面（全圖位移 0），所以沿用 B 的切格幾何直接改從這張取樣；每格自動判斷來源——向量版在人物框內多出的特效／血跡像素超過 40 個（第 2 列的雷電火焰踢 B12/B13、第 5 列的濺血受擊 B35）就退回舊 B 表，其餘 44 格用向量版（`novector` 全部退回）。
  - **「把之前的全都重來，以這張圖（向量版動作表）為基準去做動作的點圖」→ V 表重建**：`ref/clean_v.py` 先塗掉向量表上的白色格號（小的白色連通塊、四周幾乎全是背景的才算）→ `ref/cells.py V`（`jk_actions3v_clean.png`，血跡加入特效種子）切出 45 格 → `ref/split_v.py` 把特效相連而黏在一起的兩對格子切開（V12 雷電踢＝切格器另外吐出的左人物＋合併格左半的雷電火焰特效、V13 炎踢＝右半；V38 吹き飛び／V45 倒れ 在原圖 x218 切開）→ `analyze_b.py` 量 V 表 → `refine2.py x2`（新增材質 **blood**（暗紅濺血，在受擊格上）與 **dust**（腳邊淡灰塵），並移除向量表的細分隔線：格子邊緣 5 欄內、左右鄰欄幾乎全空的深色高欄，由內往外掃兩遍）。`src/jk-moves.js` 的 build() 整個以 V 格重寫（構え V0、構え直し V1–V4、步行 V5–V8、拳 V11、義手ストレート V25、義足ミドル V15→V14（殘影）→V16（塵）、横薙ぎ V10（大殘影）、ハイキック V15→V12（雷）→V13（炎）、袈裟斬 V29→V30（弧殘影）、刺突／連斬・回天／居合用 V24 的伸展斬、跳躍 V17/V18/V20/V21、空中 V22/V23–V24/V12、電磁 V25–V28、投げ V29/V31/V30、防禦 V32/V33、受擊 V34（血）/V37/V35、よろけ V36/V37、吹き飛び V38→倒れ V45、起身 V44→V17、勝利 V39–V43、敗北 V44）；蹲攻擊仍用 A 表、量子爆裂的爆炸仍用 C44（向量表沒有）。`src/sprite.js` SCALE／RES 登錄 V。
  - **「好好的仔細分析」「每一個動作都拆開依據部位比較」→ 為什麼遊戲裡的圖不像動作表，以及修法**。使用者把遊戲截圖與動作表的步行格圈起來比較。分析（`ref/compare_parts.py`，每格分頭／上身／腰裙／腿四個部位，量「與動作表的平均色差（0–255）／顏色數／邊緣能量比（1＝細節等量）／漏掉的像素」，圖在 `ref/art/compare/V<i>.png`：動作表｜舊格｜新格｜誤差圖）：
    - 舊做法（82px 格＋每材質壓成 3 階＋人工外框）：每個部位的平均色差 39–49，顏色只剩 13–19 色（動作表每個部位有 870–1650 色），邊緣能量 1.2–1.4 倍（硬外框比原畫更「刺」）。臉、髮絲、義足板片全被壓成色塊，這就是截圖裡看起來「頭一團、臉看不清」的原因。
    - 而且遊戲畫布是 960×540（RS＝2），82px 的格子畫上去每個精靈像素被放成 2×2，只用了一半的解析度。
    - 新做法（`refine2.py raw`）：格子改成 **164px＝動作表的原始像素 1:1**（每個精靈像素就是原圖的一個像素，不壓色、不加外框、不合成眼睛），遊戲以 0.5 世界倍率繪製＝畫布 1:1；每格用「調色盤＋RLE」壓縮（`prle`，`src/sprite.js decode()` 解碼），檔案 4.0MB（比 82px 原始 RGBA 還小）。結果：平均色差降到 7–10、顏色 180–230 色、邊緣能量 0.9 ≈ 動作表本身。
    - 引擎：`src/sprite.js` SCALE A／B／C／V＝0.5（畫布不放大、`frame.w/h/ox/oy/figBox` 換成世界 px、`frame.ds`＝0.5、`pw/ph`＝像素尺寸）、RES＝4；`game.js` 的 img 項帶 `w/h`、影子與刀道具的矩陣乘 ds、光彈用 `worldW/H`；`gl.js` 用 `it.w/h`；`tools/strip.js` 依 ds 縮放；`__game.renderOnce()` 供面板隱藏時測試。判定框（K＝1，世界 px）不變。
  - **「不要留下分隔痕跡」「定點的位移不太大」「這些圖也是一樣的分析方式」**：(1) 縮放過的格子（步行等 s＞1）在 1:1 取樣時視窗會小於一個原圖像素而變空，整格被打出一格一格的透明線（那就是截圖裡的「分隔痕跡」）——`refine2.window()` 視窗空時改取最近的原圖像素；(2) 錨點改為「上身核心欄的中心」（人物高度 28–55% 的列裡、像素數 ≥ 最大值 60% 的欄），不再用雙腿中心，踢腿或前衝時身體不會整個左右跳；(3) `compare_parts.py V A C` 對 A、C 表也做同樣的逐格逐部位比較（129 格：新版色差 5.6–7.8、顏色 173–226、邊緣 0.93–0.94、漏像素 3.7–6.3%）；(4) 無編號版沒有第 2 列最後一格（回身＋塵土），該格自動退回去格號的向量版取樣（`FALLBACK`）；`refine2.py raw tag:V` 可只重跑一張表。
  - **「場景也精細畫 背景加入會動的物體」**：舞台不再經 `chunky()` 減半再放大——`src/stage.js` 本來就以 720×270（1 世界 px）畫的，現在直接以這個密度繪製（比之前細一倍，與 1:1 的人物相稱）。`STAGE.anim(t)` 以時間為函數產生會動的背景（不需狀態）：34 片櫻花瓣隨風飄落擺動（每 5 片有 1 片在人物前面）、校門兩盞燈與路燈的光暈閃爍、近景大樓的窗戶不時亮滅、三條雲慢慢飄過月亮（遠景視差 0.35）、星星閃爍、每 14 秒一群蝙蝠飛過、每 26 秒一隻黑貓沿牆頂走過（兩格步態）；`game.js` 的 `stageAnim()` 把它們轉成畫面座標的 rect 項（背景項在人物之前、`front` 項在最後），2D 與 GL 的 rect 都支援透明度。與向量版同版面（全圖位移 0），人物細節接近原 B 表（義足板片、義手節、刀柄纏繩）但線條乾淨、雷電與火焰在同一格；切格幾何沿用去格號版的 V 切格，只換 `refine2.py` 的 `SHEETS['V']` 來源，重跑 `analyze_b.py` 與 `refine2.py x2`。
  - **格鬥動作點圖方法（網路檢索＋之前學的一起用）**：每招＝起手（可讀的預備動作，40–100ms）→ 殘影格（50ms，一格弧形）→ 命中格（60–110ms，hold）→ 追隨／回收（70–120ms）；關鍵姿勢先定（預備、擊中、追隨），三格看得懂才算清楚；命中時 shake／hitstop；受擊 3 格、吹き飛び 3 格＋著地 2 格；步行 4 格、待機 2 格呼吸＋構え直し 5 格。來源：[Artemisia — How to animate a fighting game](https://www.artemisiacollege.com/feeds/blog/fighting-game-animation)、[Tsugumo — Making a fighting game sprite](http://www.petesqbsite.com/sections/tutorials/tuts/tsugumo/chapter9.htm)、[Sprite-AI — how to animate pixel art](https://www.sprite-ai.art/guides/how-to-animate-pixel-art)、[Frame-based collisions](https://dominik-haas.itch.io/doms-blog/devlog/993744/frame-based-collisions)，加上先前的 Slynyrd 七拍、Boyle 連段、Munguia 表與 16-bit 圖解。
  - **「學習 affinity」→ 親和力分區 `segment()`**：原圖相鄰像素顏色差 ≤ 34 者連成區域（union-find），小於 8px 的區域併入最相近的鄰區，每個「區域」而非每個像素決定材質與色調（就是畫本身的色塊＝群聚陰影）。實測後臉部會被大片膚色區域淹掉（小臉在 2×2 視窗下更需要逐像素多數決），所以預設仍是逐像素，`regions` 旗標可開。Photopea（Cloudflare 機器人驗證擋住）與 Affinity（桌面軟體、瀏覽器面板拒絕該網站、本機未安裝）都無法由我操作；等價的分析（像素放大、取色、直方圖、分區）都用腳本做，並輸出 `ref/art/affinity/`（B 表＋4px 格線與切格框、材質分區圖、調色盤色票、82px 全格一覽）給你在 Affinity 裡開來檢視或手修。

## 做法

畫面 480×270、角色約 96～110px（KOF 尺寸）：頭、手、腳是手打點陣；上身用「材質圖」由骨架自動上明暗與接縫；四肢是圓柱明暗的筆畫；長髮是帶髮縷的飄帶。


全部點陣都是程式畫的（沒有圖片檔）：

- `src/px.js` — 1x 光柵器：材質色階、部件分離邊、外框、翻轉／旋轉。
- `src/rig.js` — 共用骨架：手繪點陣部件（頭、上身、裙、鞋）＋ IK 擺放的四肢筆畫、上身傾斜、長髮飄帶、受擊框。
- `src/jk.js` `src/vamp.js` `src/maid.js` — 三位角色（女僕含狼化型態）的點陣與破損變化。
- `src/anims.js` — 所有動作逐格定義：預備→殘影→命中→追隨→收回，含判定框與傷害。
- `src/fx.js` — 揮擊殘影、命中火花、塵土、電光等效果。
- `src/stage.js` — 480×180 的夜晚校門舞台（視差捲動）。
- `src/game.js` — 60Hz 固定步進：輸入、物理、判定、部位傷害、投射物、CPU、回合流程與 HUD。

檢視工具：`node tools/sheet.js out.png 8 jk poses.js`（姿勢表）、`node tools/anim.js out.png jk light heavy 5`（動作分格，紅框＝判定框）、`node tools/build.js`（打包成 `dist/index.html`）。
